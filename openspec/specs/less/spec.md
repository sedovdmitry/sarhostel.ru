# Less Specification

> Generated by openlore v1.2.0 on 2026-11-09 16:38

## Purpose

Provides reusable LESS mixins that SHALL encapsulate cross-browser CSS behaviors: uniform
transitions, full-cover backgrounds, themed button color variants, and typography font stacks.

## Requirements

> `less/mixins.less`

### Requirement: TransitionAll

The system SHALL apply a uniform 0.35s transition on all animatable properties, emitted with -webkit-, -moz-, and standard vendor prefixes.

#### Scenario: ApplyTransitionUtilityToASelector
- **GIVEN** A LESS selector includes the transition mixin
- **WHEN** transition-all() is invoked
- **THEN** Compiled CSS contains transition: all 0.35s for -webkit-, -moz-, and unprefixed declarations

#### Scenario: ReusableAcrossComponents
- **GIVEN** Any component (e.g. Button, Carousel) needs smooth state changes
- **WHEN** The mixin is included in its rule set
- **THEN** All property changes animate over 0.35s without per-component duplication

### Requirement: BackgroundCover

The system SHALL apply background-size: cover with -webkit-, -moz-, -o-, and standard prefixes so background imagery scales to fill its container.

#### Scenario: CoverBackgroundAcrossBrowsers
- **GIVEN** A selector uses a background image that must fill its area
- **WHEN** background-cover() is invoked
- **THEN** Compiled CSS includes background-size: cover for -webkit-, -moz-, -o-, and unprefixed targets

### Requirement: ButtonVariant

The system SHALL generate a complete themed button color variant from supplied color, background, and border values, covering rest, hover/focus, active, disabled, open-dropdown-toggle, and badge states.

#### Scenario: RestStateUsesSuppliedColors
- **GIVEN** button-variant is called with a color, background, and border
- **WHEN** The variant CSS is compiled
- **THEN** The button renders with the supplied text color, background-color, and border-color, with
transitions enabled

#### Scenario: InteractiveStatesDarken
- **GIVEN** The button is hovered, focused (.focus), active, or toggled open via a dropdown
- **WHEN** One of :hover, :focus, .focus, :active, .active, or .open > .dropdown-toggle applies
- **THEN** Background darkens by 5% and border darkens by 7% while the text color stays the supplied value

#### Scenario: ActiveStateRemovesGradient
- **GIVEN** The button is in :active, .active, or an open dropdown toggle state
- **WHEN** Those selectors apply
- **THEN** background-image is set to none so no gradient remains

#### Scenario: DisabledStateLocksColors
- **GIVEN** The button carries .disabled, [disabled], or is inside a fieldset[disabled]
- **WHEN** The element or any of its hover/focus/.focus/active states are engaged
- **THEN** Background and border remain the original supplied values (colors do not darken)

#### Scenario: BadgeColorInversion
- **GIVEN** A .badge element exists inside the themed button
- **WHEN** The variant CSS is compiled
- **THEN** The badge text color equals the button background and the badge background equals the button text
color

### Requirement: SansSerifFont

The system SHALL apply the sans-serif typography stack: 'open sans', 'helvetica neue', arial, sans-serif.

#### Scenario: ApplySansSerifStack
- **GIVEN** A selector requires the primary UI typeface
- **WHEN** sans-serif-font() is invoked
- **THEN** Compiled CSS sets font-family to 'Open Sans', 'Helvetica Neue', Arial, sans-serif

### Requirement: SerifFont

The system SHALL apply the serif typography stack: 'lora', 'helvetica neue', arial, sans-serif.

#### Scenario: ApplySerifStack
- **GIVEN** A selector requires the accent/serif typeface
- **WHEN** serif-font() is invoked
- **THEN** Compiled CSS sets font-family to 'Lora', 'Helvetica Neue', Arial, sans-serif

### Requirement: ProvideThemeColors

The system SHALL expose the brand color tokens: @theme-primary (accent color) and @theme-dark (dark/neutral color) for consumption by mixins, components, and styles.

#### Scenario: PrimaryTokenResolvesToBrandColor
<!-- openlore-test: priority=low (auto) -->
- **GIVEN** ThemeVariables is compiled into the stylesheet
- **WHEN** @theme-primary is referenced
- **THEN** It resolves to #44A69A (superseding the legacy F05F40 accent noted in comments)

#### Scenario: DarkTokenResolvesToDarkNeutral
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** ThemeVariables is compiled into the stylesheet
- **WHEN** @theme-dark is referenced
- **THEN** It resolves to #222

#### Scenario: TokensAreCentrallyOverridable
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A rebrand changes the palette
- **WHEN** The variable values are edited in variables.less
- **THEN** All components referencing the tokens update without per-component edits
