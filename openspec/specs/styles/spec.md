# Styles Specification

> Generated by openlore v1.2.0 on 2026-11-09 16:38

## Purpose

Presentational CSS module that defines the .btn-social button family: a button with an absolutely
positioned social icon column on the left and a text label that truncates with ellipsis, including
responsive size variants.

## Requirements

> `styles/buttons.css`

### Requirement: RenderSocialButtonLayout

The system SHALL render a .btn-social element as a left-aligned button that reserves a 32px icon strip on the left edge, occupied by the element's first child which is positioned absolutely with a right divider border.

#### Scenario: DefaultSocialButtonLayout
- **GIVEN** An element with class .btn-social whose first child is an icon
- **WHEN** The element is rendered
- **THEN** The button has 44px left padding, left-aligned single-line text, and the first child is absolutely
positioned as a 32px-wide icon strip with a right divider border and centered 1.6em glyph
- **AND** The button text does not wrap and overflows with an ellipsis

### Requirement: ApplySocialButtonSizeVariants

The system SHALL scale the icon strip and left padding of .btn-social proportionally when the bootstrap size modifier classes .btn-lg, .btn-sm, or .btn-xs are applied.

#### Scenario: LargeSizeVariant
- **GIVEN** An element with classes .btn-social and .btn-lg
- **WHEN** The element is rendered
- **THEN** Left padding becomes 61px and the icon strip is 45px wide with 45px line-height and 1.8em font-size
- **AND** The icon divider border is retained

#### Scenario: SmallSizeVariant
- **GIVEN** An element with classes .btn-social and .btn-sm
- **WHEN** The element is rendered
- **THEN** Left padding becomes 38px and the icon strip is 28px wide with 28px line-height and 1.4em font-size
- **AND** The icon divider border is retained

#### Scenario: ExtraSmallSizeVariant
- **GIVEN** An element with classes .btn-social and .btn-xs
- **WHEN** The element is rendered
- **THEN** Left padding becomes 30px and the icon strip is 20px wide with 20px line-height and 1.2em font-size
- **AND** The icon divider border is retained

### Requirement: TruncateOverflowingLabel

The system SHALL prevent text wrapping in .btn-social labels and must indicate clipped text with an ellipsis when the label exceeds the button width.

#### Scenario: LongLabelTruncation
- **GIVEN** A .btn-social whose label text is wider than the button box
- **WHEN** The element is rendered
- **THEN** The text stays on a single line, overflow is hidden, and an ellipsis is displayed for the clipped
portion
- **AND** No layout shift occurs in the icon strip

### Requirement: RenderSquareIconButton

The system SHALL render .btn-social-icon as a fixed 34px by 34px square button with zero horizontal padding, a fully centered first-child icon, and no divider border on the icon.

#### Scenario: DefaultSquareIconButton
- **GIVEN** An element with class .btn-social-icon
- **WHEN** The element is rendered
- **THEN** The button is 34px square with no horizontal padding, the icon fills the full width, is
center-aligned, and the icon's divider border is removed
- **AND** Text-overflow truncation rules from the base .btn-social family still apply

### Requirement: ApplySocialIconButtonSizeVariants

The system SHALL override .btn-social-icon dimensions per bootstrap size modifier: 45px square for .btn-lg, 30px square for .btn-sm, and 22px square for .btn-xs, always with zero horizontal padding.

#### Scenario: LargeIconButtonSize

- **THEN** The button is 45px wide and 45px tall with zero horizontal padding
- **AND** The icon remains full-width and centered with no border

#### Scenario: SmallIconButtonSize

- **WHEN** The element is rendered
- **THEN** The button is 30px wide and 30px tall with zero horizontal padding
- **AND** The icon remains full-width and centered with no border

#### Scenario: ExtraSmallIconButtonSize

- **AND** The icon remains full-width and centered with no border

### Requirement: ApplyBrandTheme

The system SHALL assign each brand class a white text color, its official brand background color, and a translucent black border color.

#### Scenario: BrandBackgroundApplied
- **GIVEN** A button with a brand class, e.g. .btn-facebook
- **WHEN** The element is rendered
- **THEN** Text is white, the background is the brand color (#3b5998 for facebook), and the border is
translucent black rgba(0,0,0,0.2)
- **AND** Each listed brand (bitbucket, dropbox, flickr, github, google-plus, instagram) resolves to its own
distinct brand background color

### Requirement: ApplyInteractiveStates

The system SHALL darken the brand background on hover, focus, active, .active, and open-dropdown states to a predefined darker shade of the brand color, while keeping white text and the translucent border.

#### Scenario: HoverStateDarkensBackground
- **GIVEN** A brand-colored button, e.g. .btn-google-plus
- **WHEN** The pointer hovers over or focus is applied to the element
- **THEN** The background changes to the darker brand shade (#ca3523 for google-plus) and text remains white
- **AND** Border-color remains rgba(0,0,0,0.2)

#### Scenario: OpenDropdownToggleState
- **GIVEN** A brand-colored button with class .dropdown-toggle inside an .open container
- **WHEN** The dropdown is opened
- **THEN** The button background switches to the darker brand shade consistent with hover/active states
- **AND** Text remains white and border-color is unchanged

### Requirement: ApplyFlatActiveState

The system SHALL remove the gradient background image on :active, .active, and open-dropdown-toggle states so the pressed appearance is flat.

#### Scenario: PressedButtonIsFlat
- **GIVEN** A brand-colored button with any inherited gradient background image
- **WHEN** The button is in :active, .active, or open dropdown-toggle state
- **THEN** The background-image is set to none, producing a flat pressed look
- **AND** The darkened brand background color still applies

### Requirement: ApplyDisabledState

The system SHALL preserve the original brand background and border colors on disabled buttons (via .disabled, [disabled], or fieldset[disabled] ancestors) across hover, focus, active, and .active states, and must not darken them.

#### Scenario: DisabledButtonKeepsBrandColor
- **GIVEN** A disabled brand button, e.g. .btn-bitbucket with attribute disabled
- **WHEN** The user hovers, focuses, or attempts to activate the button
- **THEN** The background remains the base brand color (#205081 for bitbucket) and border remains
rgba(0,0,0,0.2)
- **AND** No hover/active darkened shade is applied

#### Scenario: DisabledViaFieldset
- **GIVEN** A brand button inside a fieldset with the disabled attribute
- **WHEN** The button is rendered in any state
- **THEN** The base brand background and border are preserved identically to the attribute-disabled case
- **AND** The rule applies uniformly across all listed brand classes

> `styles/mobile-fix.css`

### Requirement: ForceExpandedMenuVisibility

The system SHALL the stylesheet shall force visibility: visible (with !important) on .navbar-collapse.collapse.in and .navbar-collapse.in so that an expanded mobile menu is never hidden by other visibility rules.

#### Scenario: ExpandedMenuIsVisible
- **GIVEN** A navbar collapse element with classes 'collapse' and 'in'
- **WHEN** The stylesheet is applied
- **THEN** The element is computed as visibility: visible regardless of competing rules, due to !important
- **AND** The same guarantee applies to elements matching only .navbar-collapse.in

### Requirement: StyleMobileNavbarPanel

The system SHALL within viewports of max-width 767px, the stylesheet shall style the .navbar-collapse panel with a 1px #e7e7e7 top border, an inset white box shadow, and a #f8f8f8 background color to give the mobile menu a distinct appearance.

#### Scenario: PanelStyledOnMobileViewport
- **GIVEN** A viewport no wider than 767px
- **WHEN** A .navbar-collapse element is rendered
- **THEN** It displays a #e7e7e7 top border, inset 0 1px 0 rgba(255,255,255,0.1) box shadow, and #f8f8f8
background
- **AND** Outside the 767px breakpoint these mobile panel styles are not applied

### Requirement: StyleMobileNavLinkStates

The system SHALL within the mobile breakpoint, the stylesheet shall style .navbar-nav > li > a links: default color #777 with transparent background, hover/focus color #333 with transparent background, and active color #555 with #e7e7e7 background.

#### Scenario: DefaultLinkAppearance
- **GIVEN** A mobile viewport and a nav link inside .navbar-nav
- **WHEN** The link is in its default state
- **THEN** Text color is #777 and background is transparent
- **AND** On hover or focus the link color becomes #333
- **AND** On active the color becomes #555 with #e7e7e7 background

### Requirement: EnableScrollableExpandedMenu

The system SHALL on mobile viewports, an expanded .navbar-collapse.in shall be vertically scrollable with a maximum height of 340px and forced visibility: visible so long menus remain usable.

#### Scenario: LongMenuScrollsWithinCap
- **GIVEN** An expanded mobile menu whose content exceeds 340px
- **WHEN** The menu is rendered
- **THEN** overflow-y is auto, max-height is 340px, and the panel remains visible
- **AND** Shorter menus are not clipped and do not scroll

### Requirement: PreventCollapseFlicker

The system SHALL the stylesheet shall prevent flicker of the collapse panel by setting .navbar-collapse.collapse to display: none by default and .navbar-collapse.collapse.in to display: block with visibility: visible.

#### Scenario: CollapsedPanelHiddenByDefault
- **GIVEN** A navbar collapse element with class 'collapse' but without 'in'
- **WHEN** The page renders
- **THEN** The panel is display: none and does not flash before expansion
- **AND** When 'in' is added, the panel becomes display: block with visibility: visible

### Requirement: DefineCollapsingTransition

The system SHALL the stylesheet shall define the .navbar-collapse.collapsing intermediate state as a relatively positioned panel with height 0, overflow hidden, and a 0.35s ease transition on height and visibility, governing the collapse animation behavior.

#### Scenario: CollapseAnimationParametersApplied
- **GIVEN** The collapse plugin adds the 'collapsing' class during a transition
- **WHEN** The animation runs
- **THEN** The panel animates height (and visibility) over 0.35 seconds with ease timing while remaining
relatively positioned with height 0 and overflow hidden
- **AND** Content overflowing the panel is clipped during the animation
